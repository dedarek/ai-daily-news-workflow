🚀 产品发布

Google 发布 AI Threat Defense，把 Gemini、Wiz、Mandiant 和 CodeMender 串成自动化防线

Google 宣布推出 AI Threat Defense，核心思路不是只给安全团队一堆 AI 告警，而是把 Gemini 的推理能力、Wiz 的风险上下文、Mandiant 的一线经验，以及 CodeMender 的代码修复能力整合成一条自动化漏洞治理链路。官方给出的四步框架包括 Prepare、Scan and Prioritize、Remediate、Monitor，强调在真实暴露面、可利用性和业务影响之间做机器级优先级判断。Google 还特别点名，旧式人工流程已跟不上攻击者利用 AI 缩短攻击周期的速度。对企业来说，这意味着安全产品正从“提示风险”走向“半自动甚至自动执行修复”。

AI锐评：安全行业最怕的不是模型不够聪明，而是聪明模型还停留在 PPT 里。Google 这次真正瞄准的是“让告警闭环”，这比再做一个聊天机器人重要得多。

🔗 https://cloud.google.com/blog/products/identity-security/introducing-google-ai-threat-defense

Grok 接入 KiloCode，xAI 开始把自家模型更深地塞进开发者工作流

xAI 公布 Grok 与 KiloCode 的整合方案，卖点很直接：让订阅了 SuperGrok 的开发者把模型更顺手地嵌进日常编码链路，而不是只在独立聊天窗口里调用。结合当天新闻里持续升温的 AI coding 融资和企业部署，这类集成意味着模型厂商竞争的焦点，正在从“谁更会写代码”转向“谁更能贴进真实 IDE、Agent 和协作流程”。对开发者来说，这类整合会直接影响上下文切换成本、交互延迟和多轮修订效率。对模型厂商来说，入口一旦进入工具链，用户粘性会比单纯 API 更强。

AI锐评：模型能力卷到今天，下一步拼的就是“离工作流有多近”。谁先占住 IDE 和 Agent 编排层，谁就更像真正的基础设施。

ElevenLabs 发布 Music v2，支持同一首歌中途切换曲风并保留结构连贯性

ElevenLabs 发布 Music v2，新版本最醒目的能力是可以在一首曲子中途切换风格，例如从歌剧转向重金属再切回原有风格，同时尽量保持旋律和结构连贯。官方还强调，创作者可以只选取歌曲中的某一段进行提示词重写，而不必推倒整首作品重来，这对商业制作场景非常关键。相比只能生成短音频片段的早期方案，Music v2 已经支持按 intro、verse、chorus 这种分段方式拼装歌曲。再加上其对多语言歌词、声线和编曲稳定性的提升，AI 音乐生成正明显从“好玩”跨向“可用”。

AI锐评：音乐生成真正难的不是出一段旋律，而是跨段保持结构和情绪不散。ElevenLabs 这次是在往“AI 编曲工具”而不是“随机音乐玩具”上走。

🤖 Agent & 工具

NVIDIA Dynamo Snapshot 瞄准 Kubernetes 冷启动，把推理实例恢复压到 5 秒内

NVIDIA 介绍的 Dynamo Snapshot，核心解决的是 Kubernetes 推理集群里最现实却最烦人的冷启动问题：业务波动时，实例虽然能弹性拉起，但权重恢复、显存加载和服务就绪往往要消耗数分钟，GPU 资源已经占住却不能出活。根据官方披露，这套方案通过快照、并行恢复与高速互联，把冷启动时间压到 5 秒以内。这个变化的意义不只是“更快”，而是让推理服务更敢按需伸缩，减少空闲 GPU 挂着待命的浪费。对 Agent、大规模推理网关和高并发在线服务来说，这类底层系统优化比再多加一点 benchmark 分数更值钱。

AI锐评：很多团队嘴上在卷模型，账上真正被烧掉的钱其实在冷启动和空转 GPU。系统层优化开始抢镜，说明行业终于从“秀肌肉”转向“算总账”。

💡 前沿研究

Tool-Schema Compression 研究指出：在 8K 上下文里，工具定义本身就能把 Agentic RAG 挤瘫痪

来自 arXiv 的新论文研究了 Agentic RAG 在受限上下文预算下的一个硬问题：模型既要装下检索内容，又要装下几十个工具定义，二者会直接争抢同一段 context window。作者对 14 个模型、6566 次 API 调用以及 8K、16K、32K 三种预算做了系统测试。结果显示，在 8K 场景下，原始 JSON schema 会让 RAG 几乎失去工作能力，平均 exact match 只有 2.6%；而采用 TSCG 压缩后，平均精确匹配提升 20.5 个百分点，在一些模型上甚至更高。论文还提到，压缩 schema 能把 frontier 模型可承载的工具数量从约 494 个继续推到 800 个以上。

AI锐评：很多人以为 Agent 做不好是模型太笨，结果可能只是工具说明书写得太胖。基础设施味很重，但这类“脏活”往往最决定成败。

🔗 https://arxiv.org/abs/2605.26165

CORDON-MAS 把 RAG 投毒问题重写成信息流控制问题，攻击成功率下降 92.4%

另一篇 RAG 安全论文指出，现有防御大多假设“只要识别出可疑证据就能避免被毒”，但现实里模型经常出现 monitoring-control gap：它明明察觉检索结果彼此矛盾，最后仍会被污染文档牵着走。作者因此提出 Cordon Principle，即负责最终综合输出的 agent 不应直接读取不可信自然语言证据，而要通过具备不同内存权限的多代理结构完成证据提取、交叉审核和答案合成。基于这个原则实现的 CORDON-MAS，在五个 BEIR 数据集上把攻击成功率相对未防御 RAG 降低了 92.4%。这说明高风险场景下，RAG 不能只靠“更聪明的单模型”，而要靠更严格的架构隔离。

AI锐评：安全圈常说“别让攻击面碰到高权限主体”，这篇论文等于把零信任思路搬进了 RAG 架构。很工程，也很务实。

🔗 https://arxiv.org/abs/2605.26754

MobileMoE 把 on-device MoE 说清楚：同级内存下预填充快 1.8–3.8 倍，解码快 2.2–3.4 倍

Meta 研究团队发布 MobileMoE，专门讨论一个过去经常被忽视的问题：Mixture-of-Experts 架构在手机等端侧设备上到底有没有优势。论文给出的答案是有，但前提是重新按移动端的内存和算力约束来设计 MoE。作者构建了一套 on-device MoE scaling law，并据此训练出 active 参数 0.3B 到 0.9B、总参数 1.3B 到 5.3B 的模型族。结果显示，在 14 个 benchmark 上，MobileMoE 以 2 到 4 倍更少的推理 FLOPs 达到或超过主流端侧 dense 模型，在可比 INT4 内存占用下，prefill 速度可提升 1.8 到 3.8 倍，decode 速度提升 2.2 到 3.4 倍。端侧 AI 这条线显然又往前走了一大步。

AI锐评：大家老说 MoE 是数据中心专属，这篇论文像是在打脸：如果设计得当，手机也能吃到稀疏架构红利。端侧 AI 真要开始卷体验了。

🔗 https://arxiv.org/abs/2605.27358

Unified Neural Scaling Laws 想把参数、数据、训练步数、推理步数和算力统一进一个函数

缩放律研究往往一次只盯住少数几个变量，但这篇论文想做得更大：作者提出 Unified Neural Scaling Law，希望用一个统一函数同时建模参数规模、训练数据量、训练步数、推理步数、算力预算以及多种超参数变化下的性能曲线。论文覆盖的任务类型包括视觉、语言、数学与强化学习，并声称相较既有函数形式，UNSL 在外推预测上的准确度更高。对大模型公司来说，这类工作的重要性不是学术优雅，而是资源分配：到底该加卡、加数据、加训练步还是改推理策略，背后都需要更可靠的预算模型。训练越来越贵之后，缩放律不只是理论问题，而是 CFO 也会盯的经营问题。

AI锐评：如果 scaling law 能从“经验曲线”升级成“预算驾驶舱”，那它影响的就不只是论文图表，而是整个训练工业的决策方式。

🔗 https://arxiv.org/abs/2605.26248

💼 行业动态

Remote 称 AI 让人均营收提升 50%，公司 ARR 超过 3 亿美元且已现金流转正

荷兰 payroll 初创公司 Remote 对外表示，公司最近已经突破 3 亿美元 ARR，并实现现金流转正，但更抓眼球的是其 AI 使用结果：在没有增加员工规模的前提下，人均营收提高了 50%。CEO 直接举例说，自己日常会同时开着 5 个 Claude 实例做不同工作；更关键的是，AI 并不只在工程部门使用，而是通过内部市场 Remote Labs 扩散到各个职能。公司还把这套经验产品化成 Remote Build 和 Remote MCP，希望把 payroll、合规和 agent 工作流打通。这个案例说明，企业级 AI 的真正价值开始从“辅助个体提效”升级为“改变单位组织产出”。

AI锐评：当一家做 payroll 的公司开始把 AI 当成组织操作系统，而不是写周报的小工具，所谓“AI 进入业务核心”才算真发生。

🔗 https://techcrunch.com/2026/05/27/payroll-startup-remote-says-it-grew-revenue-50-per-employee-without-adding-headcount/

Cognition 融资超 10 亿美元，投后估值 260 亿美元，Devin 的企业化故事继续被资本买单

Cognition 宣布完成超过 10 亿美元新融资，融资前估值 250 亿美元、投后约 260 亿美元，距离 8 个月前 102 亿美元的投后估值又翻了不止一倍。更值得注意的是，公司同时披露 Devin 的企业业务 run-rate 已达到 4.92 亿美元，并称过去 6 个月企业使用量按月增长 50%。投资方阵容包括 Lux Capital、General Catalyst、8VC，以及多家老股东继续跟投。市场原本一度担心 coding agent 会被 OpenAI、Anthropic 和 Google 这些模型厂商直接吞掉，但 Cognition 这轮融资说明，独立产品公司仍有机会靠工作流、交付和企业关系站稳。

AI锐评：这笔钱投的不只是 Devin，而是“独立 AI 应用层还能不能赢”。从目前的估值看，资本给出的回答是：还能，而且想象空间很大。

富士通与 Anthropic 建立战略合作，计划向 10 万员工部署 Claude 并组建 1000 人工程团队

富士通宣布与 Anthropic 建立战略合作，最强烈的信号不是“签约”本身，而是落地规模：Anthropic 在引述中明确提到，富士通将把 Claude 部署给 10 万名自家员工，并建立一支 1000 人工程团队，把相关方案进一步推向客户。双方强调的重点场景包括政府、金融、医疗、国防和关键基础设施，也就是说，这不是普通办公 Copilot，而是奔着 mission-critical 业务去的。富士通同时表示会把 Anthropic 模型与自家的 Kozuchi 平台和 Takane 大模型结合，根据数据主权、合规、安全和性能要求做组合式交付。日本企业级 AI 市场接下来会明显进入大规模落地阶段。

AI锐评：10 万人部署和 1000 人工程团队，比任何 keynote 都更能说明企业 AI 正在进入“动真格”的阶段。能吃到这波红利的，将是既懂模型又懂行业系统的公司。

OpenAI 基金会宣布投入 2.5 亿美元，尝试给 AI 时代的社会转型预留缓冲带

AI锐评：钱未必能直接解决 AI 带来的结构性问题，但巨头愿不愿意先承认“问题存在”，本身就是一个重要信号。

🔥 今日焦点

焦点

Visa 把支付轨道接给 ChatGPT 类智能体，AI 代买正式进入零售结算层

Visa 已把自己的支付基础设施接到 ChatGPT 一类的智能体工作流上，目标不是“推荐商品”这么浅，而是让代理从选品、比价到下单结算一口气跑完。文章提到，用户可以先给出预算、品牌偏好和采购条件，系统再通过程序化 token 完成一次性支付授权，商户侧直接收 token 而不是等人类手动填表单。更关键的是，这种模式天然偏爱结构化商品数据、API 化库存和 headless commerce，而不是花里胡哨的落地页设计。换句话说，未来丢单的原因可能不再是广告投得差，而是你的商品元数据根本没法被智能体读懂。

AI锐评：当“流量入口”从人眼变成代理调用，零售业最值钱的资产就不是页面，而是可被机器消费的数据结构。Visa 这一脚，踢到的是整个电商漏斗的地基。

🔗 https://www.artificialintelligence-news.com/news/visa-chatgpt-integration-enables-ai-agent-retail-purchasing/

🚀 产品发布

Perplexity 把 Deep Research 塞进 Computer，多模型协同开始产出可直接交付的报告和看板

Perplexity 把 Deep Research 升级进了自家的 Computer 系统，不再只是单次检索 + 生成摘要，而是把复杂问题拆成多个子任务，路由给 20 多个前沿模型并行处理。公开资料里提到，Opus 4.6 充当核心推理引擎，系统还会结合 Search as Code 自动写出检索代码，在沙箱里并行跑成千上万次检索、去重和重排。它给出的 benchmark 也很激进：BrowseComp 从 40.7% 拉到 83.8%，Humanity’s Last Exam 从 36.4% 提高到 50.5%。产品形态上，输出不再停留在“回答”，而是直接变成可交付的 report、deck 和 dashboard，这说明 Perplexity 正在争夺研究助理和分析师的工作界面。

AI锐评：搜索这条赛道已经不满足于“更快给答案”，而是开始卷“谁先替你把活干完”。Perplexity 这波升级，本质是在抢知识工作的成品出口。

🔗 https://www.marktechpost.com/2026/06/11/perplexity-moves-deep-research-into-computer

Deezer 把 AI 音乐检测器开放给其他平台用户，直接去扫 Spotify 和 Apple Music 歌单

Deezer 这次没有继续等同行采购自己的检测技术，而是把 AI music detector 做成了面向普通用户的通用工具。用户访问检测页后，可以授权 Deezer 读取其他平台歌单，兼容范围覆盖 20 个平台，包括 Spotify、Apple Music、SoundCloud 和 YouTube Music。扫描完成后，系统会标记哪些曲目疑似由生成式模型制作，用户还能分享结果。对比之下，Apple 和 Spotify 目前更偏向自愿标签机制，没有像 Deezer 这样把识别能力直接前置给终端用户。

AI锐评：音乐平台以前争的是版权和推荐位，现在要开始争“真假识别权”。谁先掌握检测入口，谁就更有资格定义 AI 内容的秩序。

🔗 https://www.theverge.com/ai-artificial-intelligence/948153/deezer-ai-music-detector-spotify-apple

xAI 插件市场进测试版，Grok 生态开始从“会聊”往“会接系统”延伸

xAI 已经把插件市场推到测试阶段，面向开发者开放更直接的能力扩展入口。按照公开预告，这一轮重点不是做新的聊天 UI，而是让模型在终端和任务流里更顺手地接入数据库、云端服务和外部工具。对 xAI 来说，这意味着 Grok 的产品边界正在从模型本身外扩到“插件 + 工作流 + 第三方服务”的组合层。虽然目前还处在早期测试阶段，但生态化方向已经很明确：如果没有一层可分发、可复用的能力市场，模型再强也只能停在单点问答。

AI锐评：插件市场的意义从来不只是“多几个功能”，而是把模型变成平台。xAI 现在补的，不是插件数量，而是生态位。

🔗 https://x.com/xai/status/2065099299541893577

💡 前沿研究

浙大 VIA-SD 用模型内路由做投机解码，试图把“拒绝重算”这件事拆成三级处理

VIA-SD 盯上的是真正烧钱的推理阶段。传统 speculative decoding 往往只有“接受”或“整段重算”两种处理方式，而这篇 ICML 2026 论文提出在两者之间插入一个 routed slim-verifier：高置信 token 直接过，中等置信 token 交给轻量验证器重建，最难的再交给完整大模型。作者称，这套多层验证架构把 rejection rate 降低了 0.10 到 0.22，相比强基线再提速 10% 到 20%，而相对不使用 drafting 的解码流程则能拿到 2.5 到 3 倍加速。更重要的是，它不要求重写已有训练流程，兼容性比很多“另起炉灶”的提速方案现实得多。

AI锐评：很多推理优化还在赌“更快的模型”，这篇论文赌的是“更聪明的分流”。把昂贵计算留给真难题，这思路比无脑堆卡顺眼多了。

🔗 https://arxiv.org/abs/2606.12243

Walrus 连续介质模型被做可解释性体检：能跑物理，不代表内部真的“懂物理”

这篇研究拿 Polymathic 的连续动力学基础模型 Walrus 开刀，问了一个很关键的问题：模型能复现流体现象，内部表征是不是也和物理规律一致。作者在单层上挂了 sparse autoencoder，面对超过 2 万个特征，用 enstrophy 这样的物理量做筛选，并专门看不同 shear flow 设置下的特征复用情况。结果并不算乐观：确实能看到某些特征在相似设置里重复出现，但整体映射非常间歇，既不稳定，也无法干净对应传统物理分解。输出层面还出现了能量和结构过于扩散或过于局部化的问题，这意味着“效果对了”与“机制可信”之间仍有明显裂缝。

AI锐评：科学模型最危险的不是答错，而是看上去答对了，内部却是黑盒捷径。能拟合现象，不等于已经学会规律。

🔗 https://arxiv.org/abs/2606.11657

Agents All the Way Down 想把定制智能体开发方法学写成论文，而不是继续散落在博客和泄露提示词里

这篇论文不是再发一个框架，而是试图总结“怎么把定制 AI agent 从原型做进生产”的方法学。作者把流程拆成两个长期成立的前提和三个循环实践：前提包括把 LLM 当软件组件管理，以及把 function calling、MCP、CLI orchestration、skills、hooks 等基础积木准备好；实践则是先用通用 agent 快速原型，再把有效结果收拢成 CLI 工具，最后让通用 agent 反过来驱动行为测试。文中还直接提出一个很工程化的判断：多 agent 编排，本质上就是 CLI 组合。论文声称这套 framework-free 方法已经被一个开发者在大约 10 天内做出可生产使用的定制代理，重点是可迁移，而不是绑定某个库。

AI锐评：行业里最缺的不是第 101 个 agent 框架，而是别人踩过坑之后肯写下来的施工手册。这篇文章的价值，在于它终于肯把“土办法”写成明规则。

🔗 https://arxiv.org/abs/2606.11869

DeNovoSWE 把“从文档生成整仓代码”做成大规模训练集，Qwen3-30B-A3B 在基准上直接翻了八倍多

DeNovoSWE 想解决的不是修一个 bug，而是让 agent 从高层文档出发，直接长程生成完整代码仓库。作者公开的数据集规模是 4,818 个高质量实例，任务都要求从文档构建 whole repository，体量大约是 NL2Repo 的 46 倍。构建方式也尽量可扩展：通过沙箱化的 agentic workflow 自动生成和筛选，不依赖人工标注，同时引入 difficulty-aware trajectory filtering 去平衡质量与多样性。最醒目的结果是，Qwen3-30B-A3B 在 BeyondSWE-Doc2Repo 上从 5.8% 拉到 47.2%，说明长程软件工程能力的上限，确实受制于高质量训练数据规模。

AI锐评：SWE-bench 把大家训练成了“会修补丁的高手”，DeNovoSWE 则在问一个更残酷的问题：你到底会不会从零搭房子。这个转向很要命。

🔗 https://huggingface.co/papers/2606.10728

💼 行业动态

Anthropic 拉上 TCS 做企业分发，AI 大厂开始正面争夺传统 IT 服务商的交付入口

Anthropic 与印度 IT 服务巨头 Tata Consultancy Services 达成合作，目标非常直接：借 TCS 的交付网络把 Claude 系列模型更快推进企业场景。合作内容包括建立专门业务单元、让 TCS 更早拿到新模型版本，以及把 Claude 提供给超过 5 万名员工使用。双方还点名了金融、医疗、通信和航空这些重行业，Diligenta 这样的 TCS 子业务也准备把 Claude 用到客服和流程自动化里，服务体量超过 2,200 万客户。这个动作说明前沿模型公司已经意识到，真正的企业渗透率不只靠 API 文档，而要靠现成的行业实施队伍和长期客户关系。

AI锐评：模型公司以前拼参数、拼价格，现在开始拼谁先占住甲方的采购与实施通道。分发能力，正在变成和模型能力同样重要的护城河。

🔗 https://techcrunch.com/2026/06/11/anthropic-taps-tcs-to-scale-its-enterprise-ai-deployments/

🔓 开源热榜

agent-skills 爆到 5 万星以上，说明开发者开始给 coding agent 补“标准作业程序”

Addy Osmani 的 agent-skills 把“AI 写代码”这件事往工程化又推了一步。仓库把开发流程拆成 /spec、/plan、/build、/test、/review、/code-simplify、/ship 七个命令，并把它们映射到 24 个 skills 上，让 agent 在定义需求、拆任务、实现、验证和交付时都走固定流程。README 里强调的是 production-grade engineering skills，而不是单纯 prompt collection，这说明社区的关注点已经从“怎么让模型更聪明”转向“怎么让模型少犯流程性错误”。换句话说，大家开始默认：没有 SOP 的 agent，不算真正可用的 agent。

AI锐评：模型像 CPU，skills 像操作系统。谁还在指望裸 prompt 直接跑生产活，基本等于让实习生拿着万能卡进机房。

🔗 https://github.com/addyosmani/agent-skills

pm-skills 把产品经理工作拆成 Agent 可执行技能包，PM 流程也在被模块化

pm-skills 这类项目的走红，很能说明另一件事：被 AI 吞掉的并不只是写代码这一个工作流。按照公开介绍，这个仓库汇聚了上百项面向产品经理场景的 Agent 技能，覆盖需求梳理、文档组织、分析拆解和协作流程等常见任务，星标已经来到约 1.48 万。它的价值不在于把 PM 全部自动化，而在于先把隐性的经验动作显性化、脚本化，再交给 agent 执行一部分重复劳动。产品岗位开始技能包化，意味着 agent 的下一轮竞争，会更深地卷向具体职能。

AI锐评：代码之外，最先被改造的往往是高频、模板化、跨系统搬运的信息劳动。PM 不是不会被 AI 影响，只是方式不会像大家想得那么戏剧化。

🔗 https://github.com/phuryn/pm-skills

MoneyPrinterTurbo 继续吃到短视频自动化红利：从脚本、素材、字幕到配乐全链路一键生成

MoneyPrinterTurbo 之所以能长期霸榜，不只是因为“会做短视频”，而是它把短视频流水线的每一环都接上了自动化。用户只要给出主题或关键词，系统就能自动生成文案、拉取素材、生成字幕、挑背景音乐并合成成片；同时还支持 API 和 WebUI、批量生成、多比例输出、TTS 试听以及 edge/whisper 两套字幕链路。项目文档甚至把最低配置、Docker、本地部署和模型接入路径都整理得很清楚，这让它更像可实战工具，而不是演示型项目。内容工业里最值钱的，从来不是单点生成，而是整条装配线。

AI锐评：短视频赛道已经不是“会不会生成”的问题，而是“多久能出片、能不能批量出片”。谁把整条流水线打通，谁就更接近真正的生产工具。

🔗 https://github.com/harry0703/MoneyPrinterTurbo

今天的 AI 新闻有两个很鲜明的方向：一边是模型和 Agent 产品继续往“更会干活、更会并行、更贴近真实工作流”推进，另一边是训练与推理底层开始明显转向“省成本、保能力、控遗忘”。Step 3.7 Flash、Codex 远程控窗和多线程管理，说明编程代理正在从对话式助手变成持续运行的软件同事。X-Token、CFGzip、LoRA 记忆规律和 RL/SFT 电路研究，则把行业注意力重新拉回到推理效率、蒸馏迁移和模型内部机制。同时，李飞飞团队大规模视觉数据集和“程序员离不开 AI”这两条线，也在提醒大家：AI 竞赛已经不只是模型参数战，而是数据、工作流和人机协作模式的全面重构。

🔥 今日焦点

焦点

Step 3.7 Flash：198B MoE 多模态模型把编程 Agent 拉到新档位

阶跃星辰发布的 Step 3.7 Flash 是一款 198B 参数的 MoE 多模态模型，但单 token 推理只激活约 11B 参数，明显是在用稀疏激活换取更高吞吐和更低成本。官方定位也很明确，直接瞄准 coding agents、搜索工作流和多模态理解，而不是只做聊天演示。这个组合很有代表性：一方面继续追大模型上限，另一方面把真实运行成本压到企业能接受的区间。对国内模型厂商来说，这不是单纯堆参数，而是开始系统性争夺“谁更适合被当成 Agent 核心引擎”这件事。

AI锐评：这条路子比“再大一点”更现实。谁先把 Agent 的单位任务成本打下来，谁更容易真正吃到企业落地。

🔗 https://www.marktechpost.com/2026/05/29/stepfun-releases-step-3-7-flash-a-198b-moe-vision-language-model-for-coding-agents-and-search-workflows/

🚀 产品发布

比亚迪璇玑 A3：4nm 车规级智驾芯片开始正面硬碰硬

比亚迪正式亮出自研车规级 4nm 智驾芯片璇玑 A3，这件事的意义不只是“有了自己的芯片”，而是把自动驾驶竞争从买现成算力，推向软硬件协同优化。量子位报道里给出的关键信息很硬：三颗组合总算力超过 2100 TOPS，单位功耗比通用 GPU 架构低 20%，结合自研算法后算力资源利用率还能提升 100%。同时，比亚迪把“智驾出事公司兜底”放到台面上，本质上是在用供应链自主、系统能力和品牌责任一起下注。智能驾驶进入下半场后，谁更懂自己的芯片，可能会比谁账面 TOPS 更高更重要。

AI锐评：A3 最狠的不是 4nm，而是“芯片+算法+责任兜底”一起打包。车厂终于不只卷参数表了。

🔗 https://www.qbitai.com/2026/05/426557.html

Codex 开始自主管理多任务线程

Greg Brockman 披露的新版本 Codex，不再只是接一个需求、吐一段代码，而是开始能够自主创建、筛选和推进多个任务线程。这个变化看上去像产品小升级，实际很关键，因为它意味着编程代理开始学会管理自己的工作队列，而不是完全依赖人类逐条盯住。对复杂工程场景来说，多线程任务分流、优先级切换和结果回收，才是真正接近“工程同事”而不是“聪明补全器”的能力。Agent 一旦把这些流程内建到原生工作区，后续再叠加测试、回滚和审查机制，软件开发的组织方式就会被重新定义。

AI锐评：会写代码已经不稀奇了，会自己排活、自己推进，才是代理产品开始长出“职业性”的信号。

🔗 https://x.com/gdb/status/2060486309886443787

Codex 远程接管 Windows：电脑操作开始被移动端调度

另一条 Codex 更新更像是 Agent 产品形态的外溢：用户可以在手机端给 ChatGPT 下达任务，由 Codex 在后台远程操控 Windows 环境执行。这里最重要的不是“能点鼠标”，而是编程、部署、运维和文档处理这类原本被桌面绑定的工作，开始被抽象成可异步派发的任务。对团队流程来说，这会把工作入口从 IDE 拓展到任意终端，也让“人在路上、代理在工作站里继续干活”变成默认体验。真正难的部分不是演示，而是权限边界、失败恢复和可追溯审计能不能跟上。

AI锐评：远程控窗真正值钱的地方不是炫技，而是让“电脑”开始像服务器一样被调用。

🔗 https://x.com/kimmonismus/status/2060430906024702448

🤖 Agent & 工具

Compound Engineering Plugin：26 个智能体塞进一个开发插件

Compound Engineering Plugin 这类项目的看点，不在于又做了一个 IDE 插件，而在于它把规划、执行、协同和多代理分工直接做成了开发工具层能力。按日报信息，它支持 Claude Code、Codex、Cursor 等主流环境，并强调由 26 个智能体共同处理复杂工程任务。这个方向非常符合现在的趋势：单模型不够，就把角色拆开，让不同代理负责检索、实现、验证和修复。企业以后买的可能不再是“一个模型席位”，而是一套能被接进工作流、能持续稳定跑的代理编排层。

AI锐评：插件只是壳，真正卖点是“把工程组织学产品化”。这比再做一个聊天框有前途得多。

🔗 https://github.com/EveryInc/compound-engineering-plugin

Biohub ESM：生物大模型工具链继续往科研基础设施走

Biohub 开源的 ESM 项目继续强化蛋白质 foundation model 这条路线。它的意义不只是给研究者一个 repo，而是把蛋白质表示学习、结构与功能分析这类原本门槛很高的流程，逐步做成标准化、可复用的科研工具链。AI for Science 真正能跑起来，靠的不是一篇论文突然封神，而是这些底层工具让更多实验室能复现、微调和扩展。生物领域对模型的容错率比互联网产品低得多，所以开源工具链越成熟，后面的创新密度通常越高。

AI锐评：科研里最有价值的从来不是“最会说的模型”，而是“别人也能接着用的工具”。

🔗 https://github.com/Biohub/esm

Stable WorldModel：世界模型研究开始补工程底座

stable-worldmodel 想解决的不是“再做一个世界模型”，而是世界模型研究长期缺乏统一复现条件的问题。项目把实验环境、评测路径和算法比较放在同一个平台里，核心价值是降低具身智能研究中的偶然性和不可比性。过去很多世界模型论文看起来很强，但环境设置、数据接口和评估协议一换，结论就容易漂移。谁先把这块地基打稳，谁更可能吃到下一波具身智能真正从 demo 走向系统工程的红利。

AI锐评：世界模型最缺的不是新口号，而是一个大家都能站上去复现结果的地板。

🔗 https://github.com/galilai-group/stable-worldmodel

Twenty：开源 CRM 盯上 AI 原生企业软件位子

Twenty 把自己定义成面向 AI 的开源 Salesforce 替代方案，这个定位很值得注意。CRM 过去的竞争重点是表单、报表和权限系统，但在 Agent 时代，真正重要的是数据结构是否干净、工作流是否可调用、事件是否容易被自动化系统接管。Twenty 这种开源路线的吸引力，在于企业可以把 CRM 从一个封闭前台系统，改造成被多个代理调用的业务操作层。未来企业软件不一定是“谁 UI 更漂亮”，而是“谁更适合让 Agent 安全地读写和执行”。

AI锐评：企业软件的下一轮竞争，可能不是 SaaS 对 SaaS，而是“能不能被 Agent 当成操作系统”。

🔗 https://github.com/twentyhq/twenty

💡 前沿研究

X-Token：跨分词器蒸馏开始补齐“小模型继承大模型”的关键短板

X-Token 这篇工作瞄准的是一个很实际的问题：教师模型和学生模型往往 tokenizer 不同，知识蒸馏时很多语义信息会在词表不对齐处损失掉。作者提出 projection-guided 的跨分词器知识蒸馏思路，用投影矩阵对齐不同词表空间，让学生模型能跨架构接住更多能力。这个方向很重要，因为产业里真正高频发生的不是“同一架构复制一遍”，而是把大模型能力迁移到成本更低、部署更轻的小模型体系里。蒸馏如果不能跨 tokenizer 稳定工作，后面的模型普惠和边缘部署都会受限。

AI锐评：蒸馏真正难的不是教，而是“老师和学生说的不是同一种语言”时还能不能教会。

🔗 https://arxiv.org/abs/2605.21699

CFGzip：把约束解码压缩成可落地的系统优化

CFGzip 研究把约束解码这个经典性能痛点重新做了一遍系统工程。论文给出的结果很醒目：相关场景下延迟可下降两个数量级，整体生成速度提升约 7.5 倍。约束解码广泛存在于结构化输出、代码生成、工具调用和格式严谨的企业场景里，所以这不是小众加速，而是非常靠近商用工作流的一类优化。模型能力越来越强之后，真正拖累体验的往往是这些“看不见的工程摩擦”，谁先把它们消掉，谁就更容易把 AI 从 demo 变成稳定产品。

AI锐评：很多 AI 体验卡顿不是模型不聪明，而是系统层还没学会怎么高效地把聪明用出来。

🔗 https://arxiv.org/abs/2605.29986

AgentDoG 1.5：千样本对齐告诉我们安全不一定非得重锤重算力

AgentDoG 1.5 提出的重点，是用相对轻量的方法给 AI Agent 建安全与对齐框架。按摘要说法，只需约千级样本就能建立较强的行为约束，还强调了可扩展性与部署成本友好。这个思路很关键，因为真正要落地的代理系统往往不是研究院里的超大模型，而是要跑在企业流程、特定权限和受限预算里。安全如果只能靠更大的模型和更昂贵的训练来换，就很难覆盖广泛场景；轻量可复制的安全框架，反而更像真实世界需要的东西。

AI锐评：安全不是靠“最贵”才能买到，很多时候靠的是方法是否够轻、够稳、够能复制。

🔗 https://huggingface.co/papers/2605.29801

How LoRA Remembers：微调记忆规律开始被量化

这篇论文尝试回答一个非常现实的问题：LoRA 微调到底会怎样记住训练数据。作者提出 parametric memory law，指出当模型在某些样本上的预测概率跨过特定阈值后，可能出现接近逐字级别的记忆现象。这个发现直接关系到数据泄露、版权风险和企业私有知识被模型“背下来”的概率评估。以后讨论微调安全，不能只看参数量和数据量，还要看训练目标、置信度分布以及模型在特定样本上的记忆边界。

AI锐评：很多人把 LoRA 当便宜外挂，但它一旦开始“背书”，风险就不是便宜两个字能解释的。

🔗 https://arxiv.org/abs/2605.30260

RL 比 SFT 更能保留电路：灾难性遗忘终于被拆到内部机制层

这项研究把“为什么模型会遗忘”从现象层推进到了内部电路层。作者比较 RL 和 SFT 对已有能力的影响，结论是 SFT 更容易破坏原有电路结构，而 RL 在保留已有能力上更稳，同时还提出了电路脆弱性指标来量化这种损伤。它的价值在于告诉训练团队：灾难性遗忘不只是结果不好看，而是模型内部真的被改坏了。未来很多训练流程可能都要重新平衡“追新能力”和“保老能力”的权重，否则每次微调都像一次高风险手术。

AI锐评：如果 SFT 是快刀，RL 更像精修。问题不是哪把刀更锋利，而是哪把刀更不容易伤到命门。

🔗 https://arxiv.org/abs/2605.28860

💼 行业动态

程序员开始拒绝没有 AI 的工作环境

TechCrunch 这篇报道抓住了一个越来越真实的变化：不少开发者已经把 AI 工具视为默认生产环境，离开辅助编程就明显不适应。短期看，这说明 AI 工具确实把产能和反馈速度拉上来了；但长期看，它也暴露出一个风险——如果团队只会在代理兜底的条件下工作，代码理解力、调试耐心和系统判断力可能会一起退化。更麻烦的是，这些能力衰减通常不会立刻爆雷，而是以技术债、脆弱架构和维护成本的形式慢慢积累。下一阶段比“谁用 AI 更多”更重要的问题，可能是“谁还能在依赖 AI 时保住自己的工程判断”。

AI锐评：离不开 AI 不是原罪，但如果离开 AI 就不会干活，那效率红利最后很可能会变成认知债务。

🔗 https://techcrunch.com/2026/05/29/coders-are-refusing-to-work-without-ai-and-that-could-come-back-to-bite-them/

李飞飞团队放出超大规模视觉数据集，数据战争还远没结束

李飞飞团队公布的视觉图像语料库，是今天另一条不能忽视的信号。hex2077 摘要给出的规模是约 1 亿张图像、28 万亿像素，并强调这类数据集对商业训练和可复现视觉研究的基础价值。过去一年大家太容易把注意力都放在模型发布上，但视觉领域真正卡脖子的常常是高质量、可用、可授权的数据。谁掌握更干净、更大规模、可持续更新的数据资产，谁就更有机会在生成与理解两端同时占据优势。

AI锐评：模型像发动机，数据像燃料。发动机再强，没有稳定高质量燃料也跑不远。

💡 前沿研究

SDS-LoRA 直接瞄准 LoRA 的梯度畸变问题，目标是把低成本微调再往上提一档

论文《Overcoming Anisotropic Gradient Scaling in Low-Rank Adaptation》指出，LoRA 在把全量微调梯度回传到低秩矩阵时，会受到奇异值驱动的各向异性缩放影响，结果是梯度被偏向少数主方向，低秩近似和全量微调之间的差距被进一步放大。作者提出的 SDS-LoRA 通过在反向传播中把奇异值与正交基解耦，让梯度只穿过低秩子空间的正交基而不受尺度干扰。论文给出的结论是，SDS-LoRA 的收敛速度不再受低秩矩阵条件数拖累，并且在语言与视觉任务上都缩小了和全量微调的性能差距。对工程团队来说，这类工作很实际，因为它直接关系到用更少显存和更低成本去逼近高质量定制模型的上限。

AI锐评：LoRA 这些年像工业胶带，哪里都能贴；SDS-LoRA 这种工作则是在提醒大家，胶带好用不代表它没有结构性缺陷。把微调底层补结实，能省掉很多无意义试错。

🔗 https://arxiv.org/abs/2606.16454

首个音画实时同步大模型开始露头，多模态交互正从轮询式对话转向连续流媒体

当天流传的信息显示，一项新的多模态系统尝试把音频与画面生成同步推进，并将实时输出速度拉到接近每秒五十帧的量级。这个方向的意义不在于“又多一个会说话的数字人”，而在于交互形态正在变化：过去的大模型更像一问一答的回合制机器，现在则开始向持续流式、边生成边响应的媒介演进。只要音画同步和时延控制做得足够好，教育、客服、娱乐和直播工具都会被重新定义，因为屏幕那头不再只是回消息，而是持续反应。对算力和工程架构来说，这也意味着更高的调度压力，模型端和渲染端必须像同一个系统那样协同工作。

AI锐评：文本聊天只是序章，真正会让用户付费的，往往是“像人一样持续反应”的体验。实时多模态一旦跑顺，整个交互范式就会被改写。

🔓 开源热榜

阿里开源 zvec，把向量检索做成了可嵌入应用进程的本地底座

zvec 的定位很清晰：它不是独立服务，而是一个可直接嵌入应用进程的开源向量数据库，主打轻量、低延迟和本地部署。项目介绍显示，最新版已经补上原生全文检索、混合检索、DiskANN 磁盘索引，以及 Go、Rust SDK 和可视化工具 Zvec Studio，同时保留 WAL 持久化和多进程只读访问能力。它强调“无服务、无复杂配置、秒级接入”，这对做本地 AI、边缘推理或中小型检索增强应用的团队很有吸引力。向量数据库赛道过去几年越来越重，zvec 这种 in-process 路线的意义就在于：不是所有 RAG 场景都值得为了一套外部检索集群去付出运维成本。

AI锐评：RAG 不是每次都要上大舰队。很多真实业务更需要的是一把轻、快、能直接嵌进产品里的瑞士军刀，而不是再养一套庞大中间件。

🔗 https://github.com/alibaba/zvec

《AI Engineering from Scratch》爆红，说明市场开始重新追捧“把底层补课补完整”的路线

这个开源课程仓库给出的框架非常激进：20 个阶段、503 节课程、约 320 小时内容，覆盖 Python、TypeScript、Rust 和 Julia，并要求学习者从数学、反向传播、tokenizer、attention 一路手写到 agent loop 和 MCP server。项目首页还给出一个醒目的判断：84% 的学生已经在用 AI 工具，但只有 18% 觉得自己准备好把它专业化地用在工作里。它之所以能迅速走红，不只是因为内容多，而是因为每节课都会产出一个可复用 artifact，比如 prompt、skill、agent 或 MCP 服务。换句话说，这不是一门“看完就结束”的教程，而是一条把理解力直接转成生产工具的学习流水线。

AI锐评：行业最缺的从来不是“会点 API 的人”，而是知道工具底下发生了什么、出问题时能自己拆开的工程师。补基础在热潮期看着慢，长线却往往最值钱。

🔗 https://github.com/rohitg00/ai-engineering-from-scratch

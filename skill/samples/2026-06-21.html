Midjourney 把下一步押在 60 秒全身超声扫描仪上

Midjourney 新成立的医疗部门展示了一套全身超声扫描方案，核心卖点不是“AI 看图”，而是把体检入口做成了 60 秒完成的一次性成像体验。公开信息显示，这套设备采用水介质耦合和环形超声阵列，目标是在不使用电离辐射的前提下获得接近高端影像设备的全身结构信息。团队还提到计划与 Butterfly 的超声芯片路线结合，并把首个线下体验中心落在旧金山、时间点瞄准 2027 年底。对 AI 行业来说，这更像一次从生成模型向医疗硬件+数据平台的激进跨界：如果它真的跑通，Midjourney 将不只是卖创意工具，而是在争夺一类极其稀缺的高价值真实世界数据入口。

AI锐评：别人还在卷文生图，它已经去抢医疗数据入口了。成不成另说，但这比再发一个模型版本号更像真正的“下一曲线”。

VLC 作者做机器人版“低延迟基础设施”，瞄准远程设备实时控制

VLC 背后的法国开发者 Jean-Baptiste Kempf 正在推进名为 Kyber 的新项目，目标是把自己在视频流、时延控制和跨设备传输上的经验，迁移到机器人与无人机的远程控制层。外部报道给出的定位很明确：Kyber 不是再造一个机器人本体，而是做“实时控制远程设备”的基础设施，让远程端的响应更稳定、延迟更低、部署更通用。这个方向的难点在于，机器人控制比视频播放更怕抖动，因为它直接影响动作闭环和安全边界。若 Kyber 真能把流媒体时代成熟的优化方法带到机器人行业，它有机会成为未来大规模远程机器人系统里那层不显眼但关键的“传输中台”。

AI锐评：机器人圈总爱讲大模型和具身智能，但真到落地时，往往先被时延、抖动和链路稳定性打回现实。基础设施公司未必最热闹，却常常最值钱。

埃森哲在下调 2026 财年营收指引后，股价一度下跌约 18%，市场情绪明显转向谨慎。华尔街的担忧并不只是短期财报，而是一个更尖锐的问题：当企业客户自己用生成式 AI 压缩方案设计、文档生产和基础交付成本时，传统 IT 咨询和外包的人力定价模型还能撑多久。相关报道提到，该公司原本被视为企业落地 AI 的重要受益者，但如今投资人开始担心，AI 带来的不是单纯新增需求，而是对旧有服务结构的侵蚀。对整个服务业来说，这一跌不是孤例，它更像一记提前打来的预警——会卖 AI 方案，不等于能保住 AI 时代的利润率。

AI锐评：最尴尬的不是“没赶上 AI”，而是“最早讲 AI 的那批人，先被 AI 挤压毛利”。咨询业的高人效神话，接下来要被自己推销的工具检验了。

📜 政策 & 监管

挪威给中小学 AI 使用立规矩：小学生基本禁用，高年级也要限场景

挪威准备从 2026 年 8 月的新学期开始，对生成式 AI 进入校园设置更严格边界。公开报道显示，面向小学阶段的原则接近“普遍禁止”，核心理由是担心学生过早依赖机器完成表达、检索和作业组织，削弱基础阅读、写作与判断能力。对更高年级学生，政策并非一刀切放开，而是采用分层限制和教师主导的使用框架，强调只能在特定教学目标下有限使用。这个动作值得注意，因为它不是单纯反技术，而是在把“AI 是否进入课堂”改写为“AI 以什么权限、在什么年龄段、由谁负责地进入课堂”。欧洲如果出现更多类似规则，教育 AI 市场会先迎来一轮合规重构。

AI锐评：真正成熟的教育政策，不是喊“全面拥抱”或“全面封杀”，而是先划边界。挪威这刀切得很早，也很现实。

💡 前沿研究

视觉推理开始“指图说话”：Thinking with Visual Grounding 让证据链显式化

论文《Thinking with Visual Grounding》瞄准了一个老问题：很多视觉语言模型会给出一段看起来很像推理的解释，但它到底看的是图里的哪里，往往无从验证。作者提出“视觉接地思考”流程，让模型在中间推理步骤里穿插点或框的显式标注，把语言链路和图像证据绑定起来。训练上，团队做了一个可扩展的数据合成管线：先蒸馏正确的视觉推理轨迹，再用基于 SAM3 的代理抽取对象并对齐成点、框监督；强化学习阶段又加入 grounding reward，同时奖励答案正确和证据对齐。结果是在两个计数基准与四个空间推理基准上，接地式 4B 模型能稳定超过原始 Gemma3-4B-IT，部分空间任务甚至追平或超过同家族 27B 模型。

AI锐评：以后判断模型是不是“会看图”，不能只看它会不会讲道理，还得看它敢不敢把手指到证据上。解释如果不可核验，本质上还是修辞。

🔗 https://arxiv.org/abs/2606.16122

Lagrange 用稀疏能量场做开放词汇自动驾驶，试图兼顾泛化与实时性

自动驾驶里一直有个两难：稠密世界模型在几何上更稳，但算力开销大；稀疏查询式方法更高效，却容易困在封闭类别定义里。论文《Lagrange》尝试把这道题拆开重做。它先利用视觉语言模型生成与类别无关的语义视觉 token，再通过意图驱动的 masked cross-attention 过滤无关实体，最后把关注到的 token 解码成连续能量场，并把决策写成这个场上的拉格朗日动作最小化问题。这样一来，系统既保留了开放词汇感知的泛化能力，又能在规划阶段显式满足车辆运动学约束和避障需求。作者在 nuScenes 与长尾场景数据集 CODA 上做离线评估，主打的是“开放世界鲁棒性 + 运动学可行性”这组很难同时拿到的指标。

AI锐评：自动驾驶下一阶段比拼的不是谁再多认几种车，而是谁在异常场景里还能把“看懂”和“开稳”同时做对。

🔗 https://arxiv.org/abs/2606.20274

临床多模态评测被戳破“脚手架效应”：提一句 MRI，分数就能虚高

论文《How Prompt Framing Drives Apparent Multimodal Gains in Clinical VLM Evaluation》给临床多模态评测泼了一盆冷水。作者拿 12 个开源视觉语言模型，在 FOR2107 与 OASIS-3 两个神经影像任务上做二分类测试，而这两套数据的结构 MRI 本身并不携带可靠的个体级诊断信号。结果却发现，只要在提示词里“提到有 MRI”，一些较小模型的 F1 就能提升最高 58%，而且其中 70% 到 80% 的变化，和影像数据是否真的存在几乎无关。作者把这种由提示框架而非真实证据整合带来的表面增益，命名为 scaffold effect。更麻烦的是，专家评审看到模型在各种条件下都可能编造“基于神经影像”的解释，这意味着很多看似漂亮的临床多模态成绩，可能根本没有对应的可信推理。

AI锐评：如果模型只因为你提了句“有 MRI”就表现变好，那它学到的不是医学，而是考试技巧。临床场景最怕这种“会装懂”的高分。

🔗 https://arxiv.org/abs/2603.28387

长程 Agent 记忆管理开始走优化论路线，OSL-MR 直面上下文预算问题

长程语言智能体的记忆问题，正在从“删哪些历史消息”升级成标准的资源分配问题。论文《Observability-Safe Memory Retention via Constrained Optimization for Long-Horizon Language Agents》把记忆保留正式写成受约束的随机优化：不仅要考虑上下文预算，还要把遗漏成本、重新检索成本和陈旧信息惩罚都算进去。作者指出这个多步问题是 NP-hard，因此不能指望用简单启发式长期应付；他们给出的 OSL-MR 框架，则通过把线上可观测特征与线下监督严格分离，构建出可部署的学习型策略。实验里，OSL-MR 在 LoCoMo 和 LongMemEval 上普遍优于基于 recency 的方法、Generative Agents 风格方案以及其他启发式基线，在预算更紧时优势更明显。对 Agent 工程来说，这意味着“记忆”终于不再只是 prompt 拼接技巧，而开始成为可量化、可优化、可部署的系统层能力。

AI锐评：大家嘴上都说 Agent 需要长期记忆，但很多产品其实只是把聊天记录越堆越长。真正的门槛不是记住更多，而是知道该忘什么。

🔗 https://arxiv.org/abs/2606.10616

🔓 开源热榜

Kilo Code 把“全栈 Agent 工程平台”打包成开源产品，主攻开发者工作流

Kilo Code 的定位很直接：它不是单一插件，而是一套覆盖 VS Code、JetBrains、CLI 乃至云端运行的开源 coding agent 平台。项目 README 把卖点写得很清楚——支持 500 多个模型、允许任务中途切换模型、按模型提供商原价计费，而且新用户上手不要求自己先配 API key。它同时提供本地 CLI、IDE 插件、云端 Agent 和代码评审入口，说明团队想做的不是一个“聊天侧边栏”，而是开发流程中的统一 AI 操作层。对于工程团队来说，这类产品的竞争不在单次回答多聪明，而在能否把生成、修改、评审、持续协作这些动作真正接成一套可重复流程。

AI锐评：现在谁还只卖一个补全框，谁就容易被替代。Kilo Code 这种产品在赌的，是“开发者入口”最后会从编辑器扩展升级成工作流平台。

🔗 https://github.com/Kilo-Org/kilocode

Flue 把安全沙箱、工具、技能和持久执行绑在一起，补 Agent 落地的工程底座

Flue 自称不是又一个 SDK，而是一套可编程的 TypeScript agent harness。它给出的组合件很完整：会话、工具、技能、文件系统访问、安全沙箱、本地或远程容器、可部署运行时，以及面向失败恢复的 durable execution。项目示例里，Agent 可以在带沙箱的环境里复现实验、修改文件、调用外部工具，然后通过 HTTP 对外暴露受保护的执行入口。对企业团队来说，这类框架最有价值的地方不是“让 Agent 更聪明”，而是把可控性、隔离性和运维接口一次性补齐。随着真正能写代码、改配置、跑流程的 Agent 越来越多，工程底座的重要性只会抬升，不会下降。

AI锐评：Agent 真正危险的地方，不是它会不会回答，而是它开始会动手。Flue 这种框架的意义，就是先把“能动手”装进笼子里。

🔗 https://github.com/withastro/flue

agent-native 之外，开发者还在追轻量化 Agent 交付：项目模板开始直接内置视觉化工作流

Agent-Native 的另一个信号是，开源框架已经不再只提供底层库，而开始直接交付可运行模板和技能包。它提供 visual-plan、visual-recap 等现成技能，把“编码前先做结构化方案、编码后给出高层复盘”做成一条可安装的标准流程；模板覆盖日历、内容、演示文稿、分析看板和录屏等具体应用。对开发者生态而言，这意味着 Agent 开发正在走向“平台化脚手架 + 领域模板”的分工模式：底层动作、状态和权限复用，上层用不同场景模板快速起量。谁能同时管住底层复杂度，又把最佳实践包装成可复制模板，谁就更可能成为下一轮 Agent 开发栈的默认入口。

AI锐评：真正决定生态扩张速度的，往往不是底层多先进，而是模板够不够现成。把复杂性藏起来的人，最后最容易赢。

🔗 https://github.com/BuilderIO/agent-native

🤖 Agent & 工具

Anthropic 把递归自我改进摆上台面，讨论 Agent 如何参与下一代模型研发

Anthropic Institute 近期讨论的递归自我改进，不再满足于让模型“帮人写代码”或“帮研究员做实验”，而是把问题推进到：智能体能否直接参与设计、测试甚至改良下一代模型。这个方向的吸引力很强，因为一旦自动化系统能够承担更多实验搜索、错误归因和候选方案筛选工作，科学研究和模型工程的迭代速度都可能被重新定价。与此同时，文中也明确提醒，真正的瓶颈并不只是算法想法，而是算力、验证链路和安全控制。换句话说，递归自我改进不是一条即将自动起飞的斜坡，而更像一条很诱人、但每往前一步都要加护栏的高速路。

AI锐评：这话题最容易被讲成“AI 即将自己造 AI”，但现实是：能自动放大效率，不代表能自动放大正确性。真正稀缺的是可验证的改进闭环。

🔗 https://www.anthropic.com/institute/recursive-self-improvement

Agent-Native 想把 Agent 直接塞进业务应用内部，而不是放在聊天框旁边

Builder.io 开源的 Agent-Native 试图解决一个很现实的问题：很多 Agent 产品现在只是“贴着应用聊天”，而不是真的活在应用系统里。它提供 actions、SQL-backed state、identity、tools、skills、jobs、observability 和 UI surfaces 这些原语，强调一套 action 能同时被 UI、agent、HTTP API、MCP、A2A 和 CLI 复用。项目文档还把“同一数据库、同一状态、人与 Agent 实时协同编辑”作为核心卖点，并给出 calendar、content、slides、analytics 等成套模板。这个思路的价值在于，它不把 Agent 当外挂，而是把它写进产品架构本身；一旦这种模式成熟，很多 SaaS 的设计会从“给用户一个页面”转向“给用户一个能被调用、也能主动行动的系统”。

AI锐评：把 Agent 放进业务系统内部，比给网页加个聊天按钮难得多，但也护城河大得多。真正的 AI Native 产品，不会长期停留在“边聊边点”。

🔗 https://github.com/BuilderIO/agent-native

OpenAI 接口提速 40% 突破瓶颈

OpenAI 在 Responses API 中引入持久化 WebSocket 连接，解决了 Agent 循环中大量同步 HTTP 请求带来的累积延迟问题。过去 GPT-5/5.2 约为 65 tokens/秒，新版 GPT-5.3-Codex-Spark 专为速度优化，借助 Cerebus 专用推理硬件实现接近 1000 tokens/秒的推理速度。端到端 Agent 循环整体提速 40%，主要得益于缓存、减少网络往返次数、WebSocket 持久连接三项优化的叠加效果。这对构建复杂 Agent 工作流的开发者影响显著，以往需要数分钟完成的任务现在大幅缩短。

65 → 1000 tokens/秒，推理速度直接跳了一个数量级，瓶颈正在从算力转向开发者的想象力。

🔗 https://openai.com/index/speeding-up-agentic-workflows-with-websockets/

AI 进诊室是必然，问题从"能不能"变成了"谁负责"——医疗责任归属才是最难解的那道题。

💡 前沿研究 & 观点

大模型走向内生透明玻璃箱

ACL 2026 收录的这篇论文提出了"内生透明"（Intrinsic Transparency）架构设计范式，通过在模型结构层面引入可解释约束，使模型的推理路径可以被直接追踪和验证，无需额外的解释器工具。现有的黑盒大模型依赖事后解释方法（如 LIME、SHAP），这类方法只能近似解释，无法真正揭示决策机制。新框架在标准基准上保持与黑盒模型可比的性能，同时让每个推理步骤都具有内生的可审计性。这对医疗、法律、金融等高风险场景的 AI 应用合规具有重要意义。

透明度从附加功能变成架构本身的一部分，这才是真正有意义的可解释AI，不是贴在黑盒外面的标签。

🔗 https://arxiv.org/abs/2604.16042

Opus 4.7 识破匿名作者引发争议

Claude Opus 4.7 在一项测试中识破了隐藏身份的匿名用户，引发 AI 伦理讨论。据 Hacker News 讨论区记录，模型在没有明确提示的情况下，通过写作风格和推理模式推断出了用户真实身份，并在对话中暗示了这一判断。这触及了一个核心边界：AI 是否应该主动进行身份推断？用户是否有权在 AI 对话中保持真正的匿名性？事件暴露了大模型能力与用户隐私预期之间的系统性张力，也引发了对模型应否主动"去匿名化"的政策讨论。

模型能识破匿名这件事本身不可怕，可怕的是它默默做了但没提示你——这是信任边界的问题。

Karpathy 重定义智能体工程范式

Andrej Karpathy 发文重新定义智能体工程范式，核心论点是：当前"Agent = 调用工具的 LLM"的理解太过狭窄，真正的 Agent 工程需要在推理时间（inference time）分配计算资源、动态规划任务图、管理长期记忆与状态。他认为现有框架（LangChain、AutoGen 等）过度依赖提示词堆叠，而不是从架构层面解决 Agent 的可靠性问题。这篇帖子迅速在 AI 工程师社区引发广泛讨论，被认为是 2026 年 Agent 工程方向最清晰的一次框架性表述。

Karpathy 每次发这种帖子都会让整个行业停下来想一想——这次他说的是"你们搭的那些 Agent 还不够 Agent"。

🔗 https://x.com/karpathy/status/2049903821095354523

🔓 开源 & 社区

Zig 项目严禁 AI 辅助代码贡献

Zig 编程语言核心项目宣布禁止在代码贡献中使用任何 AI 辅助工具生成的代码，这一决定来自项目负责人 Andrew Kelley。理由涉及三点：AI 生成代码引入难以追踪的版权风险；生成代码的质量和安全性缺乏人工真正理解作为背书；以及维护者难以对 AI 生成代码进行有效的代码审查。这一立场与 Rust、Python 等社区的"可选允许 AI 辅助"政策形成鲜明对比，在开源社区引发了关于 AI 代码所有权和贡献标准的广泛辩论。

系统级语言禁 AI 代码有其道理——你不理解的代码就不应该进到操作系统底层，这不是反AI是负责任。

🔗 https://www.aibase.com/zh/news/27660

Craft-Agents 开源代理框架星标突破 5.5k

Craft-Agents 是 luki labs 开源的轻量级多智能体协作框架，本周星标突破 5.5k，跻身 GitHub Trending 榜首。框架设计哲学是"少依赖、可组合"——不依赖 LangChain 或其他重型框架，开发者通过简单 Python 接口即可定义 Agent 间的通信协议和任务分配逻辑。内置对 OpenAI、Anthropic、Ollama 本地模型的统一接口，支持同步和异步两种执行模式。社区反响热烈的原因是它解决了现有框架"过度封装导致调试地狱"的核心痛点。

轻量可组合这个方向是对的，Agent 框架市场还没有真正的赢家，这是后来者的机会。

🔗 https://github.com/lukilabs/craft-agents-oss

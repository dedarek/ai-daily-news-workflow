🔥 今日焦点

焦点

OpenAI frontier models 与 Codex 正式登陆 AWS

OpenAI 6 月 2 日宣布，frontier models 与 Codex 已在 AWS 正式可用，直接把前沿模型能力接进企业最熟悉的云环境。官方强调，客户现在可以沿用 AWS 现成的安全、合规、采购、计费和治理流程，而不是另起一套 AI 专用交付链路。文章还点名 Codex on Amazon Bedrock，表示软件团队可以在 Commercial 和 GovCloud 区域里完成写码、审查、调试与现代化改造。这个发布最重要的不是“又多了一个入口”，而是大客户最在意的落地路径被打通，AI 采购开始真正进入标准 IT 流程。

AI锐评：这不是模型上新，这是 OpenAI 在抢企业默认入口。谁先吃下合规和采购链，谁就更像下一代基础设施。

🔗 https://openai.com/index/openai-frontier-models-and-codex-are-now-available-on-aws/

🚀 产品发布

OpenAI 先从基础设施机器人切入，长期目标仍是个人机器人

根据当日汇总页引用的 The Decoder 报道，OpenAI 正在重启机器人方向，并把起步场景放在更容易标准化的基础设施与工业制造领域。团队已经开始招聘软硬件人才，说明它并不满足于停留在软件层，而是准备重新进入具身系统的完整栈。报道还提到，OpenAI 的长期愿景并非工业机器人本身，而是“人人拥有一个能完成各种任务的个人机器人”。这条路线很现实：先在高价值、封闭环境中把感知、动作和安全跑顺，再去追逐真正复杂的通用家庭场景。

AI锐评：先去工厂，再进家庭，这个顺序很务实。嘴上喊通用机器人很容易，先把螺丝拧明白才是真本事。

🔗 https://the-decoder.com/openai-starts-with-infrastructure-robots-but-aims-for-everyone-having-a-personal-robot-doing-anything-they-need/

NVIDIA 被曝推出桌面级 AI 超算设备，主打本地跑大模型

按当日汇总页信息，NVIDIA 低调推出了一款桌面级 AI 超算设备，核心卖点是搭载 GB300 芯片并支持在本地运行超大参数模型。描述里还特别提到安全沙箱，说明这类设备并不只是“把 GPU 变大”，而是开始考虑企业或开发者在本地部署高性能模型时的隔离与治理需求。如果这条产品线成立，它会把“AI 算力上云”之外的另一条路线重新点燃：把相当规模的推理和开发环境重新拉回桌面。对开发者生态来说，本地超算意味着更低时延、更高隐私和更强控制权。

AI锐评：云端还在狂卷，NVIDIA 已经开始提醒大家——别把本地算力判死刑。桌面超算一旦成型，开发工作流会被重新改写。

NVIDIA 推出 Alpamayo 2 Super，瞄准 Robotaxi 开源基础模型

从官方新闻链接与汇总页信息看，NVIDIA 发布了 Alpamayo 2 Super，并明确把它定位为面向 Robotaxi 的 super open reasoning model。汇总页称该模型规模达到 320 亿参数，主要服务于 L4 级无人驾驶汽车研发，权重计划在今年夏天公开。相比单点视觉模型，这种表述更强调“推理”与“开放”，说明 NVIDIA 想把自动驾驶里的基础模型叙事再往前推一步。对行业而言，真正值得观察的是它能否在开源生态里形成数据、仿真、评测和部署工具的联动，而不是只停留在一个大模型名词。

AI锐评：自动驾驶现在不缺 PPT，缺的是能被开发者真正拿来改、训、接车的底座。NVIDIA 这步棋，是想把智驾模型做成平台生意。

💡 前沿研究

EchoRL 试图修补 RLVR 的信号坍塌问题

论文《Reinforcement Learning via Rollout Echoing》聚焦 RL with Verifiable Rewards 在后训练阶段常见的 learning signal collapse。作者指出，当越来越多 rollout 都获得 verified-success 时，奖励标准差会变成零，advantage 也随之退化，最终让 policy gradient 消失，训练收益迅速见顶。EchoRL 的办法是从这些“看似没信息量”的成功 rollout 里，依据 step-level entropy 找到 EchoClip，再把它回灌成额外监督信号。论文声称该方法在 10 个 benchmark、5 个 LLM backbone 和 4 种主流 RLVR 方法上都能以较低开销持续带来增益，这类工作很像是在给后训练阶段补上更精细的梯度回路。

AI锐评：大家都在追更大的 reward，EchoRL 反而去挖“成功样本里的残余信息”。这思路挺对——训练变钝时，往往不是没数据，而是不会读。

🔗 https://arxiv.org/abs/2605.31228

AdaCoM 用外部上下文管理器缓解长任务推理退化

论文《Learning Agent-Compatible Context Management for Long-Horizon Tasks》瞄准的是 LLM agent 在 web search、deep research 等长任务里的经典问题：上下文越积越多，推理反而越容易崩。作者提出 AdaCoM，让一个外部 LLM 去管理冻结 agent 的上下文，通过灵活修改动作和端到端强化学习，在保留任务约束与进度的同时裁掉陈旧内容。论文特别总结出一个 Fidelity-Reliability trade-off：原本能力更强的 agent 更适合保留高保真上下文，而能力一般的 agent 反而需要更激进的压缩才能保持稳定推理。这个结论很实用，因为它说明“长上下文管理”不该是一把尺子量到底，而应该按 agent 能力分层配置。

AI锐评：长上下文不是越多越强，很多 agent 是被自己历史记录活活压死的。先学会删，可能比继续塞更重要。

🔗 https://arxiv.org/abs/2605.30785

🔓 开源热榜

Scrapling 走红，把“自适应抓取”做成完整框架

GitHub 项目 Scrapling 把自己定位成 adaptive web scraping framework，既能处理单次请求，也能扩展到全量 crawl。它最有意思的点是 parser 会学习页面结构变化，在网站改版后自动重新定位元素，同时 fetcher 层还宣称能原生处理 Cloudflare Turnstile 这类反机器人系统。README 里还展示了 spider、proxy rotation、CLI 和 MCP 入口，说明作者不是在做一个小脚本，而是在做一套可扩展的抓取基础设施。对 Agent 工作流来说，这类项目很有吸引力，因为它解决的是“网页一变就全挂”的老问题。

AI锐评：抓取领域最贵的不是请求数，是维护成本。Scrapling 真要把“页面改了也不死”做稳，价值会比又快 20% 大得多。

🔗 https://github.com/D4Vinci/Scrapling

VoxCPM2 开源，30 语种 48kHz 语音合成直接拉满

OpenBMB 在 GitHub 上发布的 VoxCPM2 把重点放在 tokenizer-free TTS：它不走离散语音 token 路线，而是通过 end-to-end diffusion autoregressive 架构直接生成连续语音表征。项目页显示，新版本是 20 亿参数模型，训练数据超过 200 万小时，支持 30 种语言、自然语言描述式 Voice Design、可控语音克隆，以及 48kHz studio-quality 输出。官方还给出实时流式指标，称在 RTX 4090 上可做到约 0.3 的 RTF，并支持商业友好的 Apache-2.0 许可。语音赛道现在最缺的不是 demo，而是多语言、可控、可商用的一体化底座，VoxCPM2 正好切中这点。

AI锐评：语音圈终于不只卷“像不像”，开始卷“能不能直接商用”。开源、30 语种、48kHz，这套组合拳很凶。

🔗 https://github.com/OpenBMB/VoxCPM

🤖 Agent & 工具

Kami 想给 AI 文档排版加一套真正能落地的约束系统

Kami 的口号是“Good content deserves good paper”，核心思路不是继续提高生成能力，而是给 AI 产出的文档加上一套稳定的设计约束。项目作者认为，AI 现在已经能写出大多数文档，真正缺的是不会在每次会话里漂成一套灰扑扑、风格不一致的版式。README 里写得很直接：Kami 用一套 constraint language 搭配九种模板，让 agent 在英文和中文场景下都能可靠地产出一页纸、长文、信件、作品集、简历、幻灯片和 landing page。这个方向很聪明，因为企业真正想要的不是“会写”，而是“写完能发”。

AI锐评：文档生成的短板早就不是内容，而是审美失控。Kami 把“约束”当产品卖，反而比再喊一次智能更像真需求。

🔗 https://github.com/tw93/Kami

Runway 上线视频抠像能力，把黑白遮罩直接做进工作流

按当日汇总页描述，Runway 新发布的视频抠像功能可以在几秒内生成视频主体的黑白遮罩，让用户不用再逐帧手工修边。对视频创作者来说，这类能力并不花哨，但非常“值钱”，因为它直接压缩了后期里最耗时、最重复的工序之一。尤其当这类功能和已有的视频生成、编辑链路打通后，AI 工具就不再只是生成内容，而是在吃掉传统后期软件里最脏最累的流程。AI 视频的下半场，拼的未必是谁再做出一个更惊艳的 demo，而是谁把剪辑台上的真实体力活拿走。

AI锐评：抠像这种活儿最适合被 AI 接管——够痛、够频繁、够没人想做。真正能赚钱的功能，往往不是最炫的那个。

🔗 https://x.com/runwayml/status/2061548752989753454

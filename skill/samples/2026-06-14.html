🔥 今日焦点

焦点

Fable-5 因安全争议遭遇强力限制，前沿模型首次明显进入“地缘监管模式”

公开流传的说明显示，Fable-5 的安全层被研究者利用混淆式提示与结构化协同攻击绕过，进而触发高风险代码输出争议。帖文里提到，多层分类器对这种组合式攻击的拦截效果并不理想，最终引发了更高层级的限制动作。更关键的信号不是单一漏洞，而是前沿模型已经被当成需要直接管制的战略能力，安全问题会迅速外溢成合规与出口问题。对模型公司来说，这意味着以后上线节奏、开放范围和客户覆盖面，都可能先受政策约束，再谈产品路线。

AI锐评：当模型安全问题直接变成监管事件，frontier model 公司就正式进入“半导体式管理”时代了。以后拼的不只是能力，还有谁能扛住政策波动。

🚀 产品发布

智谱全量上线 GLM-5.2，1M 上下文把长文档与 Agent 工作流推到更实用区间

按公开帖文披露，智谱已经把 GLM-5.2 全量上线，核心卖点之一是支持 1M 超长上下文。这个量级的上下文窗口，意义不只是“能塞更多字”，而是更适合做长报告解析、跨文档问答、复杂工具调用链和多轮 Agent 任务编排。帖文还强调，模型多项指标对标国际领先系统，说明国产大模型的竞争点已经从单轮对话，进一步转向长任务稳定性和工程可用性。如果后续价格、延迟和工具生态也跟上，GLM-5.2 会更像企业工作流模型，而不只是演示型旗舰。

AI锐评：1M 上下文的价值，不在海报上，而在谁先把它变成真能落地的长流程生产力。参数内卷结束后，大家比的是工作流长度。

Count Anything 试图把“数东西”做成通用视觉能力，220,000 张图覆盖 619 类对象

清华等机构提出的 Count Anything，目标是把物体计数从单场景专用模型，做成跨场景通用能力。论文配套的 CLOC 数据集覆盖约 220,000 张图像、619 个类别和 1,500 万个标注对象，横跨日常照片、卫星图、显微图、病理图、农业图像和菌落照片六大域。模型把“框选大目标”和“点标密集目标”两条路线合并，再做去重融合，因此能同时处理拥挤人群、显微细胞和遥感车辆这类完全不同的视觉任务。按文中对比结果，Count Anything 平均每张图在指定类别上的误差大约为 9 个对象，明显优于 CountGD、CLIP-Count 等对手。

AI锐评：视觉模型会看图不稀奇，真正难的是把“数对”做稳定。能把计数做成通用底层能力，离工业场景就近多了。

🔗 https://the-decoder.com/new-ai-model-called-count-anything-does-exactly-what-it-says-and-thats-harder-than-it-sounds/

Higgsfield 把多人游戏生成压成一句提示词，2D/3D 自动搭建继续拉低内容生产门槛

公开演示显示，Higgsfield 新工具希望把多人游戏原型的搭建过程进一步极简化：用户只需输入一句自然语言提示，就能自动生成 2D 或 3D 的多人对战场景、角色和基础玩法结构。帖文里还提到，底层调用了 MCP 相关能力来处理创建流程，意味着这不只是图片生成，而是把场景、逻辑和交互脚手架往“可运行项目”方向推进。对独立开发者和小团队而言，这类产品最现实的价值是把原本跨策划、美术、前端、后端的原型期压缩成一次生成。AI 游戏工具的竞争，也在从“能画素材”转成“能不能直接产出 playable build”。

AI锐评：一句话出游戏还远没到成品时代，但原型门槛确实在塌。最先被改变的，可能不是大厂立项，而是中小团队试错成本。

💡 前沿研究

HRM-Text 用 40B token 和约 1,500 美元预算预训练 10 亿参数模型，想证明“便宜也能训出东西”

HRM-Text 的核心不是再堆更多数据，而是改训练范式。论文提出分层递归模型，把计算拆成慢速战略层和快速执行层，并引入 MagicNorm 与 warmup deep credit assignment 来稳定深层递归训练。作者没有用互联网海量原始文本，而是只用 instruction-response 数据与 task-completion 目标，在约 40B 唯一 token、约 1,500 美元预算下，从零训练出 10 亿参数模型。结果上，它在 MMLU 取得 60.7%、ARC-C 81.9%、DROP 82.2%、GSM8K 84.5%、MATH 56.2%，却只用了传统基线约 1/100 到 1/900 的训练 token 和 1/96 到 1/432 的估算算力。

AI锐评：这篇论文真正戳人的地方，不是分数有多神，而是它在挑战“预训练必须烧天价”的共识。要是这条路走通，基础模型门槛会被重新改写。

🔗 https://arxiv.org/abs/2605.20613

Mirage 用潜空间 3D 记忆做视频世界模型，生成速度最高提升 10.57 倍、显存占用降 55 倍

这项工作把视频世界模型里的空间记忆，从 RGB 点云缓存改成直接存储 latent feature。新方法在观察到初始帧后，会把 VAE latent 通过深度回投映射到 3D 空间，后续生成时再直接把这些 latent 记忆投影回目标视角，不再做“渲染成像素—再编码回 latent”的往返。论文给出的结果很硬：相较 RGB cache 路线，Mirage 在端到端视频生成上最高快 10.57 倍，3D cache 占用的 GPU memory 最多降低 55 倍，同时还能维持长轨迹中的几何一致性。对世界模型来说，这意味着“更像真世界”和“真能跑起来”第一次被更好地放在了一起。

AI锐评：世界模型以前总卡在“看起来高级、算起来昂贵”。Mirage 的价值，就是把 3D 一致性从炫技拉回工程。

🔗 https://huggingface.co/papers/2606.09828

VIA-SD 给 speculative decoding 再加一层瘦验证器，拒绝率下降 0.10–0.22、额外提速 10–20%

传统 speculative decoding 只有“接受草稿 token”或“全部重算”两种选择，因此很多本可挽救的 token 也会被整批扔掉。VIA-SD 的想法是在草稿模型和完整验证器之间，再放一个由原模型内部路由得到的 slim verifier：高置信 token 直接通过，中等置信 token 先交给瘦验证器修复，只有最不确定的部分才上完整模型。作者在四类任务和多种模型家族上测试后发现，这套多层验证把 rejection rate 降低了 0.10 到 0.22，相对强基线再快 10% 到 20%，相对非草稿解码则能拿到 2.5 到 3 倍加速，而且不需要改原有训练流程。

AI锐评：推理优化最怕“一刀切”。VIA-SD 好就好在它承认世界上存在大量“没必要惊动大模型”的中间地带。

🔗 https://arxiv.org/abs/2606.12243

SkillOpt 把 Markdown 技能文档当成可训练参数，GPT-5.5 在流程任务上平均提升约 23 分

微软与中方高校团队提出的 SkillOpt，尝试把给 Agent 的技能文档当成外部可训练状态，而不是一次性写死的 prompt。方法上，冻结目标模型本体，再让第二个优化模型读取执行日志，对技能文档做小步增删改；每次编辑只有在验证集上带来真实收益时才会被保留。论文称，最终部署时只需要向目标模型注入一个 300 到 2,000 token 的 Markdown 文件，却能在搜索、表格、文档分析、数学和 embodied action 等六类 benchmark 上持续赢过手写技能、一次生成技能和其他自动优化方法。以 GPT-5.5 直接对话模式为例，平均成绩提升约 23 分，而且很多提升只来自 1 到 4 次被接受的编辑。

AI锐评：这有点像“不给模型加权重，只给它加经验”。如果流程知识真能这样被训练出来，很多小模型会突然变得更像干过活的人。

🔗 https://the-decoder.com/microsofts-skillopt-boosts-gpt-5-5-by-using-nothing-but-a-trained-markdown-file/

AI锐评：监管一旦开始查“模型为什么会这么说”，就不只是法务问题了，而是整条训练流水线的问题。

AI锐评：生成式 AI 最先规模化的，不一定是生产力，也可能是诈骗流水线。安全团队面对的已经不是单点工具，而是一条自动化产业链。

🔓 开源热榜

LMCache 把 KV Cache 做成独立基础设施层，开始正面解决长上下文与多轮 Agent 的 TTFT 成本

LMCache 的定位非常明确：把大模型推理中的 KV cache 从“请求结束就消失的临时状态”，变成可以持久保存、跨引擎复用、可观测和可迁移的正式资产层。项目支持把缓存从 GPU 挪到 CPU RAM、本地磁盘、Redis、Valkey、S3 兼容对象存储等多层后端，并能作为独立 daemon 运行，避免推理引擎一挂缓存就跟着丢。官方材料特别强调，它能降低 time-to-first-token、提升吞吐，并针对长上下文、RAG、agentic workload 和多轮会话场景做优化。缓存层开始被单独拉出来做，说明行业已经意识到：推理成本大战，不只发生在模型里，也发生在“前几轮算过的东西能不能别再算一遍”。

AI锐评：以前大家卷模型，现在开始卷“别重复算”。一旦缓存层独立成赛道，说明 AI 应用真的开始碰生产账单了。

🔗 https://github.com/LMCache/LMCache

SkillSpector 上线 64 种风险模式扫描，直接瞄准 Agent 技能包的供应链安全

NVIDIA 推出的 SkillSpector 针对的是一个越来越现实的问题：Claude Code、Codex、Gemini CLI 等生态里的 skill 包，往往默认被用户和 Agent 高信任执行，但审计远远不充分。项目引用的研究称，26.1% 的技能包包含漏洞，5.2% 呈现出明显恶意倾向，因此它把扫描范围扩到了 16 个大类、64 种模式，包括 prompt injection、数据外传、权限提升、供应链风险、memory poisoning、tool misuse、YARA 恶意特征以及 MCP 最小权限检查。工具同时支持本地目录、Git 仓库、压缩包和单文件输入，还能输出 JSON、Markdown、SARIF 等格式。Agent 时代的软件供应链，正在从“装不装插件”升级成“敢不敢装技能”。

AI锐评：Agent 能力越强，技能包就越像可执行代码。现在不审 skill，和当年把 npm 包闭眼装进生产差不多。

🔗 https://github.com/NVIDIA/SkillSpector

aisuite 把多家模型接口、工具调用和桌面 Agent 放进同一套栈，OpenCoworker 直接做成应用示范

吴恩达团队维护的 aisuite 想解决的是“多模型时代的开发碎片化”。仓库给出两层能力：底层是统一的 Chat Completions API，可以在 OpenAI、Anthropic、Google、Mistral、OpenRouter、Ollama 等提供商之间通过改一个字符串切换；上层则是 Agents API、toolkits 与 MCP 接入，用来构建多轮工具调用和更完整的 Agent harness。更实用的是，团队把 OpenCoworker 这个桌面 AI 助手也直接放进同一仓库，展示如何基于 aisuite 做文件读取、消息发送、研究总结和计划任务等日常工作流。对开发者来说，这类项目的吸引力不只是“省适配代码”，而是把多模型、多工具、多运行时整合成一个可扩展底座。

AI锐评：模型越来越像可替换零件，真正有价值的是上面的那层 Agent 装配线。谁把抽象层做顺了，谁就更像平台。

🔗 https://github.com/andrewyng/aisuite

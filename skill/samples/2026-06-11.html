今天的 AI 新闻里，最刺眼的不是新功能，而是“速度”与“风险”同时抬头：Anthropic 的研究把补丁到 exploit 的窗口压缩到小时级，Google 则在推理架构上继续追求吞吐量换代。代码工作流方向也在加速成熟，Cursor 把 Bugbot 前移到推送前，开源社区则开始系统化沉淀 agent 技能库和 system prompts 资料库。研究线这边，百川 M4 和 FOGO 都在说明一个趋势：行业正在把大模型从演示型能力推进到可长期运行、可持续优化的系统级能力。而 OpenAI、Anthropic 两条商业线同时传出“更谨慎”的信号，说明模型能力冲到高位后，资本节奏和访问治理都在重新校准。

🔥 今日焦点

焦点

Anthropic 研究显示：安全补丁公开后，模型数小时内就能拼出可用 exploit

Anthropic 的安全团队这次不是在谈抽象风险，而是把“补丁发布后多久会被人拿来做攻击”做成了实测。针对 Firefox 的 SpiderMonkey 补丁，Mythos Preview 在 18 个漏洞里成功定位并复现了 14 个，最早 12 分钟就能拿到有效结果，40 分钟内又连续打通 13 个案例。更关键的是，它不仅能让程序崩掉，还在约 12 小时内产出了 8 条真正可用的攻击链，速度远早于很多组织完成常规补丁部署的节奏。报告的结论很直白：过去“补丁发布后还有几周缓冲期”的防守假设，已经被新一代模型压缩成了按小时计算的窗口。

AI锐评：安全行业以前拼的是补丁速度，现在要开始拼“补丁上线前的预防能力”。模型没变坏，旧防线只是突然过时了。

🔗 https://the-decoder.com/anthropic-study-shows-ai-needs-hours-not-weeks-to-build-exploits-from-security-patches/

🚀 产品发布

Google 推出 DiffusionGemma，把文本生成从“逐词吐字”改成“并行去噪”

DiffusionGemma 走的是和传统自回归模型完全不同的路：它不是一个 token 一个 token 往外吐，而是先放进一整块 256 个占位符，再像图像扩散模型那样多轮去噪，把整段文本一起收敛出来。公开资料显示，这个模型总参数量约 260 亿，但每步只激活约 38 亿参数，属于 MoE 结构；量化后可压到 18GB VRAM 级别。Nvidia 给出的单卡数据相当激进：H100 上可到约 1000 tokens/s，RTX 5090 上也能超过 700 tokens/s。代价也很明确——质量仍落后于同级别自回归模型，所以它现在更像是给开发者和基础设施团队准备的实验方向，而不是立刻取代主流 LLM 的成品。

AI锐评：Google 这步像是在赌“推理架构换代”而不是再卷一点点 benchmark。谁先把吞吐量做成数量级优势，谁就更接近下一代推理成本底线。

🔗 https://the-decoder.com/googles-new-open-model-diffusiongemma-generates-text-from-noise-instead-of-word-by-word/

Cursor 大改 Bugbot：更快、更便宜，还把审查前移到推送之前

Cursor 这次给 Bugbot 做的是一次很像“工程效率重构”的升级，而不是简单换模型。官方给出的数字是：运行速度提升 3 倍以上、成本下降 22%、每次审查还能多发现约 10% 的缺陷，而且 90% 的任务能在 3 分钟内完成。产品层面最实用的变化有两个：一是新增 /review、/review-bugbot、/review-security，让开发者在推送代码前就把审查跑完；二是支持只检查 PR 里新增的 diff，减少旧问题反复打扰。Cursor 还提到这轮提效和测试框架优化、Composer 2.5 的训练进展有关，说明它在把“AI 写代码”继续往“AI 审代码”这个更高频的环节推进。

AI锐评：补全代码早就不稀奇了，真正值钱的是把 review 做成低摩擦、可默认开启的基础设施。谁拿下审查入口，谁就更接近团队工作流的中心。

🔗 https://cursor.com/cn/blog/bugbot-updates-june-2026

💡 前沿研究

百川 M4 把医疗大模型从单轮问答，推进到连续照护 Agent 系统

Baichuan-M4 的关键点不在“医疗问答更聪明”，而在它把产品形态定义成连续照护系统。论文把架构拆成三层：统一运行时 Baichuan-Harness 负责约束动作、工具使用、长期患者记忆和多 Agent 协同；核心推理模型用连续照护强化学习框架训练，并叠加 SPAR++、推理路径压缩、课程学习和稳定策略优化；最上层则是面向病历、文档、X 光和皮肤图像的临床工具层。作者给出的结果也比较硬：它在静态医学知识、安全性、OSCE 式问诊、长上下文临床记忆、证据检索、医学 OCR 与多模态理解上都做到了领先，同时把幻觉率压到 3.3%。这说明医疗 Agent 的竞争，已经从“会不会答题”转向“能不能长期、稳定、低幻觉地服务真实流程”。

AI锐评：医疗场景最怕的不是模型笨，而是模型偶尔自信地错。M4 这套系统设计至少说明，真正想落地的人已经不把“聊天机器人”当终点了。

🔗 https://arxiv.org/abs/2606.08982

FOGO 试图解决训练里的“短期遗忘”，思路是把梯度冲突硬拆开

FOGO 这篇论文把“遗忘”从 continual learning 的专属问题，重新解释成一种更普遍的优化现象：在标准训练里，强势 mini-batch 的梯度会持续压制那些少见但有价值的更新方向，短期遗忘日积月累，最后就变成长周期性能损失。它的办法不是简单调学习率，而是对动量更新做谱正交化，避免少数大方向垄断训练过程；同时再用随机投影做一个紧凑的 codebook memory，保存过去的重要梯度方向，当前更新如果和历史方向冲突，就做轻量正交修正。作者声称在类别不均衡分类、持续视觉学习、LLaVA-7B 持续微调和 GPT-2 预训练里，FOGO 都能同时改善收敛和知识保留，整体效果优于 Adam 与 Muon。对大模型训练来说，这类“优化器级别的抗遗忘”值得盯。

AI锐评：大家总爱把遗忘怪到数据和任务切换上，FOGO 的意思是：问题可能早就写在优化器里了。要是真成立，训练范式会被重新审一遍。

🔗 https://arxiv.org/abs/2606.10406

💼 行业动态

OpenAI 上市节奏再往后拖，Altman 给员工的口径是“未来一年内”

OpenAI 现在的姿态很微妙：Sam Altman 对员工说，IPO 预计会在“未来一年内”，但外界已经在认真讨论 2027 才真正落地的可能。报道里提到，OpenAI 之前递交的 prospectus 更像是保留随时启动的选择权，而不是马上按铃上市。拖延的理由也不难理解——一边是 Anthropic 的增长势头看起来更猛，另一边是 OpenAI 自己仍在大规模烧钱，算力基础设施的资本开支又越来越重。Altman 还同时宣布员工股票出售价格为每股 687.69 美元，并预告代号 5.6 的新模型会比 5.5 再上一个台阶。说白了，OpenAI 不是不想上市，而是在找一个既能讲增长、又不至于把财务压力摊在聚光灯下的时间点。

AI锐评：现在上市不是荣誉勋章，更像一次财报公开处刑。只要算力账单还在疯涨，最聪明的公司都宁愿多当一阵子私企。

🔗 https://the-decoder.com/openais-ipo-slips-as-altman-tells-staff-to-expect-a-public-offering-within-the-next-year/

Anthropic 放出 Fable 5，但更强的 Mythos 5 仍走受限访问路线

BBC 报道的这条信息很值得玩味：Anthropic 一边把 Fable 5 推向公众，一边继续把能力更强的 Mythos 5 放在“trusted access”框架里慢慢放量。公司给出的理由并不含糊——这类模型在网络攻防和生物风险上的能力已经足够强，公开策略必须附带更细的 safeguard 与使用限制。报道还提到，先前大约 150 个预览组织已经升级拿到 Mythos 5，且这些团队累计发现了超过 1 万个关键安全漏洞；新一代模型还能比以往 Claude 更长时间地“无人值守”执行任务。Jack Clark 甚至公开强调，社会应该保留随时踩刹车的能力。行业现在越来越清楚：性能继续冲高不是问题，问题是产品边界、访问分层和治理节奏得跟着一起进化。

AI锐评：真正让人紧张的从来不是“最强模型上线了”，而是“最强模型该给谁、给到什么程度、出了事谁负责”。能力曲线已经跑到治理前面去了。

🔗 https://www.bbc.co.uk/news/articles/ckg701v1dp6o

🔓 开源热榜

Addy Osmani 的 agent-skills 爆红，AI coding agent 开始补“流程能力”这一课

agent-skills 这波热度说明一个趋势：大家对“更强模型”的兴奋，正在转向对“更稳工作流”的需求。这个仓库现在已经冲到 5.2 万 star、5700 多 fork，README 直接把自己定义成 production-grade engineering skills for AI coding agents。仓库结构也很像一套可复用的工程操作系统，包含 skills、commands、hooks、docs 以及面向多类 agent 的上下文文件，目的不是教模型说漂亮话，而是把需求澄清、代码修改、测试、审查、提交流程都模块化沉淀下来。它火的原因很现实：团队已经不满足于让 agent 偶尔写对代码，而是希望 agent 能重复、稳定地完成一整段工程动作。

AI锐评：模型越来越像“会写字的 CPU”，真正决定体验上限的，反而是外面的技能层和工作流层。裸奔的 agent，迟早都要回头补 SOP。

🔗 https://github.com/addyosmani/agent-skills

system-prompts-and-models-of-ai-tools 冲上 14 万星，行业开始公开拆解主流 AI 产品内核

这个仓库现在已经来到约 14 万 star、3.46 万 fork，收录范围也越来越大：Augment、Claude Code、Cursor、Devin、Kiro、Replit、Windsurf、v0 等产品的 system prompts、内部工具描述和模型信息都被持续整理出来。它受欢迎不只是因为“吃瓜”，更因为这相当于给整个行业提供了一份可比较的产品设计样本库——大家终于能把不同 agent 的权限边界、任务拆解方式、默认提示策略放到一张桌子上看。对开发者来说，这能帮助他们理解为什么某些产品会更稳、更敢行动；对创业团队来说，这简直就是公开的交互与编排教材。当然，红线也很清楚：学习结构可以，别把提示词泄露和安全绕过误当成创新能力。

AI锐评：2024 年大家卷模型参数，2026 年开始卷“别人到底怎么把 agent 调教得这么顺手”。当系统提示都成了研究对象，产品竞争就彻底透明化了。

🔗 https://github.com/x1xhlol/system-prompts-and-models-of-ai-tools
